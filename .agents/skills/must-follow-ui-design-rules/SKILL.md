# ra2-explorer 前端 UI 设计强制准则

本 skill 约束 ra2-explorer 的长期产品界面，不是通用网页设计教程。进行任何前端 UI 修改或评审时，
必须同时遵循 `must-follow-project-dev-rules`；命令、验证、文档和提交规则以该 skill 为准。

## 开始修改前

1. 阅读相邻组件、样式变量、响应式规则和当前 diff，先确认已有产品合同，再决定最小改动面。
2. 判断改动属于导航、集合、详情、媒体预览、设置或独立窗口中的哪一层；不要用局部 CSS 覆盖掩盖
   错误的 DOM 层级、滚动容器或状态归属。
3. 复用现有状态、查询、选择和布局合同。新增视图不是新增一套数据语义，新增控件也不是新增一种视觉语言。
4. 涉及真实资产表现时使用 `.runtime\RA2MD` 的静态数据验证，所有截图、临时索引和派生产物写入
   `.runtime\RA2MD-Ext`；不得运行游戏目录内的 EXE。

## 已发生过的回归与对应不变量

以下问题都曾在前端演进中实际出现；修改相邻区域时必须主动防止复发。

| 历史问题 | 必须保持的不变量 |
| --- | --- |
| 主信息只有 8–10px，窄屏继续缩字 | 正文与主信息保持可读字号，窄屏改为重排或隐藏次要信息 |
| 列表或独立详情没有稳定滚动条 | 每个超长内容区拥有明确滚动容器、可见滚动条和稳定槽位 |
| “资源 / 单位”分成两套入口，分类和筛选重复 | 使用一棵语义树；单位类型是子分类，视图共享同一数据合同 |
| 位置列、完整路径、资料库状态和开发说明占据界面 | 只保留能支持用户动作或识别内容的文本 |
| 详情标题横跨画布、上下边距过大、详情只能固定尺寸 | 标题属于信息列且保持单行；上下和左右布局均可调节并记忆尺寸 |
| list 只能单列，详情内容长期纵向堆叠 | 桌面 list 双列；详情用分组、折叠和自适应列提高密度 |
| 刷新或切换布局后丢失分类、选择和滚动位置 | 按浏览上下文持久化状态，恢复前验证目标仍然有效 |
| 缺失译文仍显示空行，音频名称暴露 `.wav` | 不渲染无内容字段；面向用户显示语义名称而非格式噪声 |
| 筛选只作用于可见页或把失败状态当标签 | 查询、计数、分页和选择使用一致筛选语义；失败通过状态反馈 |
| 音频分类、文本关联和单位动作的交互含义不一致 | 依据游戏规则关联展示，点击媒体执行预览而不是下载资源 |
| VXL 只按文件尺寸估算中心，重载时清掉相机回调 | 按变换后的实际几何包围盒取景；模型清理不得销毁浏览器级回调 |

## 信息架构

1. 主工作台不设顶部工具栏。`RA2-Explorer` 位于左栏顶部，显示设置固定在左栏底部；索引状态、
   添加目录和重新扫描不作为常驻界面控件。
2. 左栏是一棵统一的语义导航树，不设置“资源 / 单位”标签切换，也不创建“核心素材”“全部资源”
   “全部单位”“游戏单位”等与现有入口重复的聚合分类。
3. 左栏必须能收起为图标栏。收起后每个仍可用入口都要有可辨识图标、`title` 和可访问名称；
   不依赖被隐藏的文字解释图标含义。
4. 分类深度服务于真实检索：单位按载具、航空器、步兵、建筑等子类组织，媒体按语音、音效、动画、
   地图等实际内容组织。不要仅因为底层文件格式不同就制造新的顶层产品分类。
5. 设置只控制用户能理解的显示和载入行为。技术格式可以作为高级设置或资源文件信息，不能支配主导航。

## 外观、字号与密度

1. 沿用 `styles.css` 的 `--bg`、`--panel`、`--panel-2`、`--panel-3`、`--line`、`--line-soft`、
   `--muted`、`--quiet`、`--red-bright`、`--amber` 和 `--green`。除新增稳定语义外，不引入一次性颜色。
2. 默认正文为 14px 左右；列表主信息和表单控件最终计算字号不得低于 12px，优先使用 13px；
   辅助元数据不得低于 11px。10px 只允许用于不承载操作、状态或识别信息的纯装饰标记。
3. 紧凑按钮和筛选控件通常保持至少 30px 高，普通按钮通常为 34–38px。复用现有 2–3px 圆角；
   只有 tag、chip 和计数胶囊使用全圆角，不把所有卡片做成胶囊或大圆角。
4. 主要层级依靠面板明度、细边框、留白和字重建立。红色只表示品牌、选中或主操作，琥珀和绿色只用于
   已有语义状态；不通过大面积渐变、强阴影或新增强调色补偿层级混乱。
5. 详情标题必须紧凑、单行、省略溢出文本，并与相邻操作在同一行。实体标题放在右侧信息列上方，
   不占用三维画布的高度；不得再用两行标题、重复类型行或大块上下内边距。
6. 相同层级的 gap、内边距、控件高度和基线保持一致。中文长文本优先换行或弹性占列，不通过缩字解决。

## 集合视图与筛选

1. 资产集合同时提供 list 与 grid。两者共享查询、筛选、排序、分页、选中、播放和加载状态，切换视图
   不得重新解释数据或清空当前选择。
2. 桌面 list 默认两列，以紧凑行比较名称和关键属性；可用宽度不足时降为一列。grid 使用响应式卡片列，
   缩略图或播放器是主内容，不重复堆放同一字段。
3. 根据当前内容类型提供有意义的筛选。单位顶层只保留阵营筛选；格式、帧动画、体素以及“缺少主体”
   不得作为多余的常驻筛选行。筛选条件必须作用于完整结果，而不是只重排当前页。
4. 语音和音效在 list 与 grid 中点击即预览；动画提供顺序播放和全帧 grid。点击单位关联动画应驱动
   主体视图中的动作，不把预览操作替换成文件下载。
5. 空结果要说明可执行的恢复动作。解析失败、缺少主体或无法预览是状态，不是假装成内容分类的 tag。

## 详情布局

1. 默认采用集合在上、宽屏详情在下的上下布局；显示设置可切换为集合在左、窄屏详情在右的左右布局。
   独立详情窗口默认使用宽屏布局。
2. 上下和左右布局之间设置可拖动分隔条，并提供键盘方向键操作、正确的 separator role、orientation 和
   当前值。调整结果必须持久化；不要用不可发现的隐藏热区代替可见交互状态。
3. 详情面板按可用宽度重排。规则属性使用三列基础网格：短值占一列，中值占两列，长值占三列；
   容器变窄时依次降为两列和一列，不依赖整个 viewport 猜测详情宽度。
4. 关联声音与关联动画分组呈现并默认展开。声音保留选中、移动、攻击等语义分组，分组标题只出现一次；
   单条关联可用两行容纳标识、原文、中文和播放控件。主体动作文件属于“资源文件”，动作预览属于画布。
5. 规则属性和资源文件默认收起，标签区域默认展开。重复组件、依赖或文件用 chip、紧凑网格或单行记录，
   不把每项拆成三行造成无效纵向长度。
6. 原文、中文或其他可选字段为空时整个字段行不渲染。用户界面中的音频名称去掉 `.wav`、`.aud` 等
   可推断扩展名；路径只在资源文件、导出、定位或排障动作附近显示。

## 滚动、响应式与状态恢复

1. 当页面根节点禁用 body 滚动时，所有集合、导航、详情和独立窗口内容区必须形成完整的高度约束链：
   grid/flex 子项设置 `min-height: 0`，实际滚动节点使用明确的 `overflow-y`。
2. 资产列表、导航树和详情使用稳定且可见的滚动条，并通过 `scrollbar-gutter: stable` 避免内容跳动。
   不依赖操作系统的覆盖式自动隐藏滚动条，也不制造 body 与内层同时滚动的双滚动条。
3. 独立详情窗口必须拥有自己的滚动上下文；验证内容短、内容长、刷新和窗口缩放，不能假设主窗口样式
   会自动产生正确高度。
4. 持久化数据源、树节点、筛选、排序、list/grid、当前选择、导航收起状态、详情布局、分隔尺寸以及
   列表和详情滚动位置。存储键应版本化，并按数据源和浏览上下文隔离。
5. 恢复状态前确认数据已加载且目标仍存在。加载中清空列表或 DOM 重排时，不得用临时的 `scrollTop=0`
   覆盖已保存位置；用同步的上下文键或恢复就绪标记避免 effect 竞态。
6. 在 820px 和 580px 附近检查布局降级。空间不足时重排、隐藏次要列或停用分隔条，不缩小必要文字。

## 媒体与三维预览

1. 不同内容使用适合其形式的浏览器：SHP 动画显示播放和帧 grid，音频显示播放、时长及可用文本，
   地图和图像显示空间/画面预览，VXL 使用可旋转、缩放和重置的三维视图。
2. VXL 默认相机必须覆盖应用 HVA/组件变换后的实际非空体素包围盒。使用八个包围盒角点在相机空间中的
   投影同时适配宽度、宽高比和高度；模型中心、重置视图和容器 resize 都使用同一份 fit 计算。
3. 释放或切换模型时只清理模型级对象，不清除 renderer、resize、projection、render 等浏览器级回调。
   至少用大小和长宽比差异明显的三个真实模型检查全部可见、视觉居中和一致边距。
4. RA2 VXL 的外观主要由体素颜色索引、所选 PAL、法线光照和玩家色映射组成，不要把缺少位图贴图当成
   纹理加载失败。调色板和阵营色控件应靠近渲染选项，以实际游戏语义命名，不添加解释性旁白。
5. 音频类型由规则关联和内容语义确定，不凭文件名或是否有人声简单互换“语音 / 音效”。有原文或中文
   时用于检索和详情；没有时不显示“暂无文本”等占位行。

## 组件与可访问性

1. 修改控件前复用相邻 DOM、class、设计变量以及 hover、focus、selected、disabled、loading 状态。
   不为一个按钮另造尺寸、图标语言或交互反馈。
2. 图标按钮必须有可访问名称和 hover/focus 反馈；只靠颜色表达的选中或错误状态还要有结构或文本信号。
3. 可调分隔条、折叠 summary、树节点、播放器和弹窗必须能通过键盘操作，并保持可见焦点。
4. 加载、错误和空状态不能造成布局突然坍塌或覆盖有效内容。错误文本要短、具体、可操作，不展示堆栈、
   内部路径、实现阶段或调试建议。

## 明确禁令

- 不新增顶部工具栏、重复产品分类、重复位置列或无动作价值的完整路径。
- 不以说明段落弥补含混命名，不展示开发进度、实现注释、资料库自述或验收话术。
- 不把底层文件格式、解析 failure 或下载动作放在内容浏览的主交互层级。
- 不用固定像素高度掩盖滚动链错误，不用 `overflow: hidden` 吞掉本应可达的内容。
- 不让新窗口依赖 opener 的滚动状态，不让 list/grid 各自维护冲突的筛选和选择状态。
- 不凭单个 VXL 文件头范围设置默认相机，不在模型重载时销毁全局渲染或投影回调。
- 不在缺少字段时渲染空行、占位 tag、“暂无”文案或纯格式扩展名。

## 最小浏览器验收

1. 先运行前端类型检查和生产构建。只改样式或组件时不因此重复完整后端测试。
2. 使用 Playwright 在真实后台数据上覆盖本次相关场景：默认上下布局、左右布局、左栏收起、分隔条拖动
   与键盘操作、list/grid、长内容滚动、独立窗口以及刷新后的状态恢复。
3. 滚动恢复必须用真实 wheel 或滚动操作产生非零位置后刷新验证；只写 localStorage 不能证明行为正确。
4. VXL 改动至少抽查小型、宽型或长型、航空器等三个差异明显的真实模型，并点击重置后检查完整可见。
5. 验收同时检查控制台/page error、横向溢出、异常空白、双滚动条、焦点可达性和中文长文本。
6. 临时 Playwright spec 使用后删除；截图和其他 QA 产物写入 `.runtime\RA2MD-Ext`，不得提交到仓库。
